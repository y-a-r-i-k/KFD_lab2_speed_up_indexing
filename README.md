## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

```src/main/kotlin/lab2/ProductSelection.kt```

**Как работает функция и почему выбран такой способ обработки данных?**

Функция принимает 3 списка: ```products```, ```recommendedIds``` и ```excludedIds```.
Затем создается словарь ```productsById``` для того, чтобы быстро сопоставлять ```id``` продукта и значение.
Создается множество ```excluded``` для быстрой проверки исключенных товаров за O(1) и ```addedIds``` для отслеживания тех элементов, что уже добавлены.

Затем строим список, который будем возвращать. Проходимся по списку ```recommendedIds``` (рекомендованных товаров), для каждого ```id``` находим товар в ```productsById```, проверяем, что он доступен и не исключен. Затем, если товар еще не был добавлен, добавляем его в выходной список и запоминаем его ```id``` в ```addedIds```.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Цикл идет по списку ```recommendedIds```, а не по каталогу, и товары добавляются в выходной список в порядке обхода. Поэтому порядок результата совпадает с порядком первого появления ```id``` в рекомендациях, а порядок каталога ни на что не влияет.

Уникальность обеспечивает множество ```addedIds```: ```addedIds.add(id)``` возвращает ```true```, только если такого ```id``` еще не было. При повторной рекомендации ```add``` вернет ```false```, и товар второй раз не добавится.

Исключенные и недоступные товары обрабатываются через проверку на построении выходного списка.
Проверка на неизвестные происходит тоже при построении итогового списка. Если данного ``id`` нет в ``productsById``, то мы просто пропускаем его.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

``O(p + r + e)`` - ожидаемое время работы

Оценка ожидаемая, потому что поиск и вставка в ```HashMap```/```HashSet``` работают за O(1) только при нормальном распределении хеш-кодов ключей. Для ключей типа ```Long``` это выполняется. Также ```id``` в каталоге уникальны по условию, поэтому ```associateBy``` не теряет товары.

- ```products.associateBy { it.id }``` - работает за линейное время O(p)
- ```excludedIds.toHashSet()``` - тоже линия O(e)
- ```HashSet<Long>()``` - просто создаем HashSet - O(1)
- Далее идет проход по списку ```recommendedIds``` - это O(r)

В итоге: ```O(p) + O(r) + O(1) + O(e) = O(p + r + e)```

**Дополнительная память:**

``O(p + e + min(r, p))`` - дополнительная память

- ```productsById``` - хранит по одной записи на каждый товар каталога - O(p)
- ```excluded``` - хранит различные исключённые ```id``` - O(e)
- ```addedIds``` - в него попадают только ```id``` подходящих товаров, каждый не больше одного раза. Их не больше, чем товаров в каталоге, и не больше, чем рекомендаций - O(min(r, p))

В итоге: ```O(p) + O(e) + O(min(r, p)) = O(p + e + min(r, p))```

**Память для результата** (отдельно): ``O(min(r, p))`` - каждый товар каталога входит в результат не больше одного раза, и товаров в результате не больше, чем рекомендаций.
